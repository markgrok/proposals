[#asio-names]
== The names

asio's targets are native and emscripten. On each, a name of asio is
Boost.Asio's own, or a type with Boost.Asio's interface where the browser
needs one of its own:

[cols="3,3,5",options="header"]
|===
| Name | Native | Emscripten

| `webcpp::asio::io_context`
| A class derived from `boost::asio::io_context`; its run family is Boost's.
| The same class: Boost's scheduler and reactor, the reactor made at
  construction, and the run family composed with the limit on the handlers
  one turn runs.

| Executors, `post`, `dispatch`, `bind_executor`, completion tokens,
  `co_spawn`, Boost.Cobalt
| Boost.Asio's.
| Boost.Asio's, unchanged.

| `webcpp::asio::steady_timer`, `system_timer`, `basic_waitable_timer`
| Aliases of Boost's.
| Aliases of Boost's, in the reactor's timer queue, which `run` waits on.

| Promises and events as operations
| None: nothing of the browser exists.
| A JavaScript promise and an event source, each an Asio operation.

| WebSocket and HTTP clients
| Boost.Beast.
| webcpp's beast library: Beast's interfaces over the browser's `WebSocket`
  and `fetch`.

| `ip::tcp`, `ip::udp`: sockets, acceptor, `resolver`
| Aliases of Boost's.
| Class templates of asio's with Boost's interfaces: each operation of a
  socket or an acceptor completes with `operation_not_supported` unless a
  transport provides it, and the resolver completes with the entries the
  browser streams of webcpp's beast library accept.

| `ssl`: `context`, `stream_base`, `verify_*`, `host_name_verification`
| Aliases of Boost's, in `<webcpp/asio/ssl.hpp>`, which brings OpenSSL
  natively, so that `<webcpp/asio.hpp>` leaves it out.
| A record of the program's TLS settings, which only the browser streams of
  webcpp's beast library read.
|===

A program includes `<webcpp/asio.hpp>` and writes `webcpp::asio::` where it
would write `boost::asio::` for the types above; every other name of
Boost.Asio, `post`, `co_spawn`, `use_awaitable`, `bind_executor` and the
rest, it keeps naming directly. The io_context is a class of its own on both
targets, so that a program sets its options the same way everywhere; its
executor is `boost::asio::io_context::executor_type` and it converts to
`boost::asio::io_context&`, so code written against either interoperates.
Every other name is an alias of Boost's natively.

The io_context takes its options, `io_context_options`, as the last argument
of each of Boost's constructors: with none, with an allocator, which it
allocates its services and its objects' state with, and with Boost's hint of
the concurrency it will see, with or without an allocator, so that Boost's
idiom `+io_context io{1}+` compiles unchanged. Its one option,
`max_handlers_per_turn`, 1000 by default, bounds the handlers one turn of
its run family runs on emscripten before it yields to the browser; 0 is
taken as 1. Natively the options are accepted and change nothing, since no
page waits on a native loop.

On emscripten, `/webcpp/asio//asio` also gives every program the
configuration Asio needs to build there, and the link flags of its
suspension variant (<<asio-building>>).
