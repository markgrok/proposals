[#wasi-limits]
== Limits

The handler hands the main only the method and the target. It reads no
request header and no request body, and sends no response header but
`content-type`. A main that needs a request's body or its headers, or to set
other headers, waits for the handler to grow: today it cannot be written with
wasi.

[#wasi-limits-allocation]
=== What it allocates

The handler's own code allocates nothing: it views the request's strings
where they are, and the response's content type where the main put it. Two
things do allocate, each through its language's default:

* *The request's strings.* The target, and an extension method's name, are
  copied into the component's memory as the host hands them over, through
  the `cabi_realloc` the bindings define, which calls wasi-libc's `realloc`.
  The handler frees them once it has written the response.
* *The response's body,* a `std::string`, which allocates through
  `std::allocator` once it outgrows the 10 characters it holds in itself on
  wasm32.

What the main allocates besides is the program's own. A program cannot yet
give wasi an allocator of its own for either.
