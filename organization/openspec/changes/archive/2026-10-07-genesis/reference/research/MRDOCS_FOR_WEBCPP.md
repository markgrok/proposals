# MrDocs for webcpp

The owner decided that every webcpp library's API reference is generated by
MrDocs, always to AsciiDoc, from Doc Comments. This note records what MrDocs
2026.9.29 offers (from its documentation, repository and releases) and what a
spike measured on xstate-cpp (`stately::xactor`, `stately::xstate`). Claims
from documentation cite a source `[Sn]` listed at the end; claims marked
**measured** come from the spike, whose commands are in section 7.

## 0. Summary

- **It works on xstate-cpp today.** The macOS arm64 binary of release
  2026.9.29 ran on the 33 public headers in about 4 s and produced the
  AsciiDoc reference (445 symbol sections with `detail` hidden) with exit
  status 0 and no error. **measured**
- **One file for one page.** `multipage: false` + `embedded: true` writes a
  single `.adoc` with no document title, `link:#anchor[...]` cross-references
  and one `==` section per symbol. Included with `leveloffset=+1` into a
  hand-written page, Asciidoctor.js 4.1.0 converted it with no warning, 1117
  internal links, 0 broken, 0 duplicate IDs. The multipage output uses
  inter-document `xref:x.adoc[]` links and is for Antora. **measured** [S20]
- **Enforcement exists, but the defaults hide work.** `warn-as-error: true`
  makes undocumented symbols, missing `@param` and missing return docs fail
  the run (exit 1). With the defaults, `auto-function-metadata` writes
  parameter and return text from the types' briefs and `auto-relates` makes a
  class with related free functions count as documented, which hides 48 of
  535 public problems on xstate-cpp. A lint run needs both set to `false`.
  No warning exists for a missing `@tparam`. **measured** [S9]
- **Rework measured on xstate-cpp's public API** (script and MrDocs agree on
  every category): 78 of 185 functions have no doc comment; the 88 documented
  functions that take parameters document none of their 143 parameters; 89
  documented non-void functions lack `@returns`; 20 of 58 classes and
  structs, 7 of 9 enums, all 37 enumerators, 13 of 21 aliases, 2 using
  declarations and 143 of 146 data members are undocumented. In total 535
  diagnostics. `detail` namespaces add 146 functions, 318 undocumented
  parameters and 120 missing returns. **measured**
- **The house style survives, partly.** The first paragraph becomes the
  brief, the "Tip:" paragraph becomes a plain "Description" paragraph, and
  all 33 file-level `/** */` comments (before the include guard) are dropped.
  **measured**
- **Blockers and risks:** no macOS x86_64 or Linux arm64 binary; the macOS
  binary needs macOS 26; no checksum file or signature is published; b2 5.5.3
  wrote no `compile_commands.json`; MrDocs's embedded Clang reads `CPATH` (it
  picked Homebrew's Boost over `deps/boost`); bundled-header mode fails on
  Boost.Asio; the header scan forces C++23, which changed one synopsis; `@` is
  a command anywhere in prose, even inside backticks; `@sa`, `@deprecated`,
  `@since`, `@todo`, `@retval` are silently dropped; ASCII hyphens in prose
  are emitted as `&hyphen;` (U+2010). **measured**

### What it needs at run time

- **No LLVM or Clang install**: Clang is embedded (LLVM 23.0.0git), and the
  Clang resource directory is bundled and passed as `-resource-dir` "so
  parsing does not depend on a Clang installation on the host" [S9
  `clang-resource-dir`].
- **A host C/C++ toolchain's headers, by default.** `use-system-stdlib` and
  `use-system-libc` default to `true`: "It probes the configured compiler to
  discover the system include paths ... every platform on which you want to
  generate documentation must also be a platform on which your library
  compiles" [S10]. The spike's log shows the probe (`/usr/bin/g++ -v -E -x c++
  -`, or `/usr/bin/clang -v -E -x c++ -` in header-scan mode). **measured**
- **A compilation database, a CMake project, or nothing** (header scan), see
  section 2. CMake is needed only when `compilation-database` names a
  `CMakeLists.txt`; MrDocs then looks in `CMAKE_ROOT`, then `PATH` [S6].

## 2. Input

### How MrDocs finds the code

Three sources [S6]:

| Source | MrDocs does |
| --- | --- |
| `compile_commands.json` | Reads it. `${MRDOCS_SOURCE_ROOT}` in it is replaced by the absolute source root, so a hand-written database can be committed [S6] |
| `CMakeLists.txt` | Configures it in a scratch directory with `MRDOCS_BUILD` set, then reads the database CMake writes [S6] |
| Header scan | With neither key nor `cmake:` set, walks `input` and makes each matching file a translation unit [S6]; the source hard-codes `clang -fsyntax-only -std=c++23 -x c++ <file>` [S17 L73-L79] |

Selection rules in the source: an empty `compilation-database` with empty
`cmake` means header scan; a `cmake:` value with no database uses
`<source-root>/CMakeLists.txt`; any other database file name is an error
[S18 L67-L122]. **measured**: a database named
`compile_commands_linux.json` failed with "Invalid compilation database
path". Without a `-std` flag in the database, MrDocs adds `-std=c++26` [S19
L322, L367-L377].

### A header-only library

A header-only library has no translation unit, and "An INTERFACE target
contributes nothing to compile_commands.json and MrDocs parses an empty
corpus" [S6]. The documented answers are a doc-only target compiling one
aggregate TU that includes every public header (the "MrDocs Builds pattern"),
or the header scan [S6]. `error-on-empty-corpus` (default `true`) turns an
empty corpus into a failure [S9].

Measured on xstate-cpp, all three give the same diagnostics:

- a hand-written database with one aggregate TU (`src/all.cpp`, 33
  `#include` lines), `-std=c++20`;
- a hand-written database whose entries are the three umbrella headers
  themselves (`-x c++ -std=c++20 ... include/stately/xactor.hpp`), so no
  generated `.cpp` is needed;
- the header scan (33 TUs, 2.2 s wall, 23 s CPU). It parses as C++23, and the
  synopsis of `~actor_system() = default;` came out as `constexpr
  ~actor_system() = default;`, which the C++20 code does not declare. A
  database with `-std=c++20` is the faithful choice.

### What Boost libraries that use MrDocs do

Six boostorg repositories carry a `doc/mrdocs.yml`: url, redis, gil,
dynamic_bitset, msm, openmethod [S11].

**Boost.URL** [S12][S13][S14][S15][S16]:

- `doc/mrdocs.yml`: `source-root: ..`, `input: ../include`,
  `file-patterns: '*.hpp'`, `exclude` of the `impl` directories,
  `include-symbols: boost::urls::**`, `include-macros: BOOST_URL_*`, a
  `see-below` list, an `implementation-defined` list that starts with
  `boost::urls::detail` and `boost::urls::**::detail`, `exclude-symbols`,
  `generator: adoc`, `base-url: https://www.github.com/boostorg/url/blob/develop/`,
  `multipage: true`, and `cmake: '-D BOOST_URL_MRDOCS_BUILD=ON -D
  CMAKE_CXX_STANDARD=20 ...'` with no `compilation-database` key [S12]. It
  also sets `private-bases: false`, which 2026.9.29 no longer knows
  (**measured**: `unknown configuration key: "private-bases"`).
- `CMakeLists.txt`: `option(BOOST_URL_MRDOCS_BUILD ...)` and, when on, one
  TU written by CMake, `#include <boost/url.hpp>`, as target
  `boost_url_mrdocs` with `BOOST_URL_MRDOCS` defined, then `return()` [S13
  L37, L155-L160]. The comment in `mrdocs.yml` reports extraction going from
  about 8 min to about 3 s with that single TU [S12].
- The docs are an Antora site: `doc/antora.yml` sets `ext: cpp-reference:
  config: doc/mrdocs.yml` and tagfiles for Boost.System, Core and Filesystem
  [S14]; `doc/local-playbook.yml` loads `@cppalliance/antora-cpp-reference-extension`
  and `@cppalliance/antora-cpp-tagfiles-extension` [S15];
  `doc/build_antora.sh` runs `npx antora`.
- CI: job `antora` on Windows, Ubuntu and macos-15 runs `build_antora.sh`
  and fails if `build/site` is missing, because "Antora returns zero even if
  it fails" [S16 L378-L441]. MrDocs itself is downloaded by the Antora
  extension; the playbook pins no version, and the extension's `version`
  default is `*`, with `master` and `develop` builds allowed [S21]. The
  extension always passes `--generator=adoc --multipage=true
  --tagfile=reference.tag.xml` [S22 L1715-L1760].

**Others**: Boost.Redis sets `warn-as-error: true` with
`warn-if-undocumented: false` and `warn-no-paramdoc: false`; Boost.GIL sets
both to `false` with `warn-as-error: false`; Boost.OpenMethod sets
`auto-function-metadata: false` [S11]. No Boost library found enforces
"every symbol documented".

### b2

- MrDocs accepts any `compile_commands.json`, so a database b2 writes would
  do [S6].
- B2's manual documents `--command-database=json` and
  `--command-database-out=file`, written by default under the root project's
  build directory [S23].
- **measured** on a copy of xstate-cpp (its b2 is 5.5.3, from Boost 1.92):
  `b2 --command-database=json test`, the same with
  `--command-database-out=<abs path>`, `--command-database json test` and
  `--command-database=json example` all exited 0 and wrote no file. This
  matches xstate-cpp's own `tools/compile_commands.py`, which reads a dry run
  (`b2 -n -a`) because "b2 5.5.3's --command-database writes nothing".
- For a header-only library b2's database is not needed: it would list every
  test and example TU (253 entries in xstate-cpp's committed one, with
  absolute paths of another checkout). A committed one-entry database using
  `${MRDOCS_SOURCE_ROOT}`, or the umbrella headers as entries, is smaller and
  portable.

## 3. Configuration (`mrdocs.yml`)

Every option is a YAML key and a kebab-case CLI flag; the CLI wins; relative
paths resolve against the directory of `mrdocs.yml` [S7]. A JSON schema is on
Schema Store [S7]. Defaults are from the options reference [S9].

| Concern | Keys (default) |
| --- | --- |
| Generator and output | `generator` (`html`; `adoc`, `xml`, `json`, `noop`), `output` (`<config-dir>/reference-output`), `multipage` (`true`), `embedded` (`false`), `legible-names` (`true`), `tagfile` (`<output>/reference.tag.xml`), `show-namespaces` (`true`), `show-enum-constants` (`false`), `global-namespace-index` (`true`), `addons-supplemental` (`[]`) |
| Inputs | `source-root` (config dir), `compilation-database`, `cmake`, `cmake-build-dir`, `includes`, `system-includes`, `defines`, `use-system-stdlib` (`true`), `use-system-libc` (`true`), `missing-include-prefixes`, `missing-include-shims` |
| File filters | `input` (`<source-root>`), `recursive` (`true`), `file-patterns` (`*.hpp`, `*.h`, ... `*.cpp`), `exclude`, `exclude-patterns` |
| Symbol filters (namespaces) | `include-symbols`, `exclude-symbols`: globs on qualified names, `*` one namespace level, `**` any depth. There is no `namespaces` key |
| Private and detail | `extract-private` (`false`), `extract-private-virtual` (`false`), `extract-private-bases` (`false`), `extract-all` (`true`: undocumented symbols are extracted), `extract-anonymous-namespaces` (`true`), `extract-empty-namespaces` (`false`) |
| Implementation-defined markers | `implementation-defined`: symbol globs; such a symbol "has no page of its own, and any reference to it renders as implementation-defined". `see-below`: the synopsis renders `/* see-below */` and members are not listed. Both have doc-comment twins, `@implementationdefined` and `@seebelow` [S9][S26] |
| Macros | `extract-all-macros` (`false`: only documented macros), `include-macros`, `exclude-macros` |
| Source links | `base-url` joined with the file path relative to `source-root`; the Antora extension can compute it (`auto-base-url`) [S21] |
| Inference | `auto-brief` (`true`), `auto-relates` (`true`), `auto-function-metadata` (`true`), `overloads` (`true`), `sfinae` (`true`), `inherit-base-members` (`copy-dependencies`) |
| Diagnostics | `warnings` (`true`), `warn-if-undocumented` (`true`), `warn-if-undocumented-namespace` (`false`), `warn-if-doc-error` (`true`), `warn-no-paramdoc` (`true`, also reports a missing return, **measured**), `warn-no-brief` (`true`), `warn-unnamed-param` (`false`), `warn-if-undoc-enum-val` (`true`), `warn-broken-ref` (`true`), `warn-unknown-config-keys` (`true`), `warn-as-error` (`false`), `max-errors` (`0`), `error-on-empty-corpus` (`true`), `log-level` (`info`) |

### Can "every public symbol documented" be an error?

Yes. The documentation calls `warn-as-error` "the usual CI setup once a
project is past the bring-up phase" [S8]. **measured**: with
`warn-as-error: true` the run exits 1. Caveats, all measured on xstate-cpp
(public API, `detail` hidden):

| Setting | Diagnostics | Undocumented functions | Missing `@param` | Missing return | Undocumented records | Undocumented enums |
| --- | --- | --- | --- | --- | --- | --- |
| Defaults | 487 | 52 | 132 | 87 | 16 | 5 |
| `auto-function-metadata: false`, `auto-relates: false` | 535 (532 + 3 namespaces) | 78 | 143 | 89 | 20 | 7 |

- `auto-function-metadata` "provides documentation for special functions
  ... [and] for missing documentation metadata, such as known types" [S9]:
  it named `limits` of `explicit actor_system(xactor::budgets limits)` "The
  object to construct from", and documented `deliver`'s `correlation`
  parameter with the brief of its type `correlation_id`. Those parameters no
  longer warn.
- `auto-relates` lists related free functions in a class's doc, and a class
  with such a list no longer counts as undocumented: `scheduler`,
  `node_set`, `machine`, `snapshot`, `state_node`, `implementations` and
  both `errc` enums were not reported with the defaults although they have
  no comment.
- No warning exists for a missing `@tparam`: an undocumented template
  parameter passed silently (probe).
- `warn-as-error` prints, after every diagnostic, "An issue occurred during
  execution. If you believe this is a bug, please report it at
  https://github.com/cppalliance/mrdocs/issues" (371 times on xstate-cpp).
  `max-errors: 40` stops after 40 and says so.
- Undocumented namespaces are not reported unless
  `warn-if-undocumented-namespace: true` (3 on xstate-cpp: `stately`,
  `stately::xactor`, `stately::xstate`).

## 4. Doc Comment syntax

MrDocs reads `/** ... */` and runs of `///` (and `//!`) and claims that "a doc
comment that compiles for Doxygen typically works here without changes" [S24].
Parsing is CommonMark-shaped: blocks first, then inlines, with MrDocs
commands added at both levels [S24].

### Commands MrDocs lists [S27]

| Kind | Commands |
| --- | --- |
| Paragraphs, headings | plain prose, `@details`, `@par [title]` |
| Lists, tables | `-` bullets, `@li`, `@arg`, HTML `<table>`, definition lists `term : definition` |
| Code | `@code[{.lang}]` ... `@endcode`, `@verbatim` ... `@endverbatim`, Markdown fences |
| Admonitions | `@note`, `@tip`, `@important`, `@warning`, `@caution` |
| Other blocks | `> quote`, `---`, footnotes `[^label]`, math `\f[ \f]` |
| Summary | `@brief`, `@short` |
| Functions | `@param[in|out|in,out] name`, `@tparam`, `@return`, `@returns`, `@result`, `@throw`, `@throws`, `@exception`, `@pre`, `@post` |
| Links between symbols | `@see`, `@sa`, `@relates`, `@related`, `@relatedalso`, `@relatesalso`, `@memberof` |
| Flags | `@functionobject` (`@functor`), `@seebelow`, `@implementationdefined` |
| Inline | `*em*`, `_em_`, `@a`, `@e`, `@em`, `**strong**`, `@b`, `@strong`, `` `code` ``, `@c`, `@p`, `~~del~~`, `==mark==`, `^sup^`, `~sub~`, HTML equivalents, `$math$`, `\f$ \f$`, `[text](url)`, `![alt](src)`, `@ref name ["text"]`, `@link` ... `@endlink`, `@copydoc`, `@copybrief`, `@copydetails`, `<br>` |

Not listed, and **measured** as silently dropped with their text and no
warning: `@deprecated`, `@since`, `@todo`, `@retval`. `@file` is dropped
too, but the rest of its comment attaches to the next declaration: in a
probe, `/** @file escape.hpp The file command. */` before `namespace probe {`
became the namespace's brief and replaced the namespace comment written in
another header. `@sa` is listed as an alias of `@see` but produced no "See
Also" in a probe, while `@see @ref run` did. **measured**

### `@` is a command anywhere

**measured** in probes: `no @param here` in prose became a parameter named
`here,` plus a doc error; `` `@param` `` inside a code span was still parsed
as a command and truncated the brief; `a@b.org` rendered as `a*.org*` (`@b`
is bold); `@Override` lost its `@`. `\@param` escapes it. xstate-cpp's
comments contain no `@` today, and one backslash.

### The brief when `@brief` is absent

The documentation disagrees with itself: "the first line (until the first
dot, question mark, or exclamation mark)" [S9 `auto-brief`], "The first
sentence of a doc comment is the symbol's summary" [S26], and "The first
paragraph is the brief" [S25]. **measured**: the whole first paragraph is
the brief, also after an explicit `@brief`. In xstate-cpp 31 of 394 comment
blocks have more than one sentence in their first paragraph; all of it shows
in member tables. `warn-no-brief` (default `true`) reports a doc with no
brief [S9].

### Where a comment can go (probe, **measured**)

| Target | Result |
| --- | --- |
| File (`/** */` before the include guard) | Dropped (Clang attaches no comment across the `#ifndef`); MrDocs has no file pages. All 33 xstate-cpp headers open with one, and none of their text is in the output |
| Namespace | Becomes the namespace's brief and description, shown in the parent's table. A namespace reopened in several headers keeps one comment: a second one replaced the first in a probe |
| Concept | Supported: a "Concepts" table, a section with the `requires` expression as synopsis |
| Macro | Only documented macros are extracted (`extract-all-macros: false`); synopsis `#define NAME` without the value |
| Enumerator | `/** */` before it and `///<` after it both work; listed in the enum's "Members" table, no own section unless `show-enum-constants: true` |
| Data member | Own section; `///<` after it works; an undocumented one warns (143 in xstate-cpp) |

### Overload sets

With `overloads: true` (default), overloads are grouped into one symbol whose
documentation is "the union of non-ambiguous metadata from the functions"
[S9]. **measured**: an overload-set section lists each synopsis with its
own brief and a "» more..." link, is titled "`scale` overloads", and showed
the `@param`/`@returns` of the one overload that had them. Each overload also
gets its own section; their anchors carry hash suffixes
(`probe-scale-05`, `probe-scale-0b`, `probe-scale-03`; constructors
`stately-xstate-node_set-2constructor-03`), so hand-written links to an
overload are fragile.

## 5. AsciiDoc output

- **Shape.** Default multipage: "every symbol gets its own .adoc file under
  the output directory, mirroring its parent-context tree", `index.adoc` is
  the global namespace [S28]. `multipage: false` writes one file at the
  `output` path; `embedded: true` "strips the doctitle so an outer page can
  pull the file in with an include:: directive" [S28].
- **Antora.** The generator is "the source format Antora and most other
  AsciiDoc tooling consume" and MrDocs builds its own site with it [S28];
  two Antora extensions run MrDocs inside the build and add a `cpp:` macro
  backed by tagfiles [S29]. They are Antora extensions; using them from a
  plain Asciidoctor.js build was not tested.
- **Outside Antora, measured.** Multipage pages each start with
  `[#anchor]`, a level-0 title made of `xref:` links, `:relfileprefix:
  ../../../` and `:mrdocs:`, and end with `[.small]#Created with
  https://www.mrdocs.com[MrDocs]#`. Their links are inter-document
  (`xref:stately/xactor/result.adoc[...]`): included into one page, they
  became `href="../../../stately/xactor/result.html"`, broken. The single
  file (`multipage: false`) uses `link:#stately-xactor-turn[...]`, emits no
  attributes and no footer, and with `embedded: true` starts at
  `[#index]` / `== Global namespace`. Every symbol is a `==` section with
  `===` subsections (Synopsis, Description, Parameters, Return Value,
  Exceptions, Member Functions, Data Members ...).
- **Included in an existing page, measured.** `include::reference.adoc[leveloffset=+1]`
  under a hand-written `== API reference`, converted with Asciidoctor.js
  4.1.0 (Asciidoctor 2.0.26) and `--failure-level=WARN`: exit 0, no warning,
  1123 IDs, 0 duplicates, 1117 internal links, 0 to a missing ID; prose can
  link with `<<stately-xactor-turn,...>>`.
- **What the text looks like.** All prose is written with HTML named
  character references: `&lowbar;` (2021 in the page), `&period;`, `&sol;`,
  `&apos;`, `&semi;`, `&colon;`, `&hyphen;` ... Asciidoctor passes them to the
  HTML, where they render; but an ASCII `-` in a comment becomes `&hyphen;`,
  that is U+2010, and any check that reads the page's text must decode
  entities. Section titles contain links (`link:#stately[stately]::...`), so
  every TOC entry does too; with `:toclevels: 2` and `leveloffset=+1` the TOC
  lists all 445 symbols. Code listings are `[source,cpp,subs="verbatim,replacements,macros,-callouts"]`
  with links inside the code, which a highlighter must keep. The "Declared
  in" line is a monospace link to `base-url` + path + `#L<line>`. The
  `[#index]` ID could clash with a host page's own.
- **Stylesheet attributes.** `stylesheets`, `stylesdir` and `linkcss` are
  emitted as AsciiDoc attributes at the top of each generated file [S28].
- **Customization.** The pages come from Handlebars templates under
  `share/mrdocs/addons/generator/adoc/`; `addons-supplemental` overrides
  single partials [S28].

## 8. What adopting MrDocs requires for webcpp

1. **A pinned binary per CI platform**, fetched and checked by SHA-256 like
   any other pin: Linux x86-64 (static) and macOS arm64 (macOS 26+). No
   checksum or signature comes from the authors; Linux arm64 and Intel Macs
   need a source build of MrDocs and LLVM [S3].
2. **A committed compilation database per library**, with
   `${MRDOCS_SOURCE_ROOT}`, `-std=c++20` and the include paths, listing the
   umbrella headers (or one aggregate TU). Not b2's database (5.5.3 wrote
   none) and not the header scan (C++23).
3. **A clean environment**: `CPATH`, `CPLUS_INCLUDE_PATH` and
   `C_INCLUDE_PATH` unset in the target that runs MrDocs, and a host
   toolchain present (system headers mode; bundled headers fail on Asio).
4. **Two runs per library**: a `noop` lint run with
   `auto-function-metadata: false`, `auto-relates: false`,
   `warn-if-undocumented-namespace: true`, `warn-as-error: true`; and the
   `adoc` run with `multipage: false`, `embedded: true`, included with
   `leveloffset=+1` into the hand-written page. `detail` namespaces as
   `implementation-defined` (Boost.URL's pattern).
5. **Comment rework**, per section 7: document every public function,
   class, enum, enumerator, alias and data member; add `@param` for every
   parameter, `@returns` for every non-void function and `@tparam` by
   review, since nothing checks it; move file-level text into the namespace
   or the hand-written page; turn "Tip:" into `@tip` or keep it as a
   description paragraph by decision; replace `(doc: #anchor)` with links the
   page resolves; escape any `@` in prose as `\@`; keep the first paragraph
   to one sentence.
6. **Doc checks that decode HTML entities** before reading text, and that
   accept U+2010 where the source has `-`.

## 9. Risks and open questions

- Platform coverage (no Linux arm64, no Intel Mac, macOS 26 minimum) and an
  unsigned, un-checksummed distribution.
- Documentation and behaviour disagree in places (brief rule, `@sa`),
  dropped commands give no warning, and diagnostics depend on two inference
  options that are on by default.
- Anchors of overloads and constructors carry hash suffixes; links from
  prose to them may break when signatures change.
- Every symbol's text is entity-encoded and titles carry links, which the
  house highlighter and doc checks must handle.
- Releases are frequent (two in September 2026) and the Antora extension
  defaults to the latest; webcpp must pin.
