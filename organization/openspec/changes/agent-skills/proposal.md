## Why

webcpp is written for coding agents as much as for people, and its rules are long: the
superproject's `AGENTS.md` and the organization's specification each run to thousands of lines.
An agent that starts a recurring task (a proposal, a port, a lane, a page) today has to find the
chapters that apply by itself. Agent skills, short playbooks an agent loads by name when its task
matches, can point it to those chapters and to the commands in order, without restating the
rules. The vendor-neutral layout `.agents/skills/<name>/SKILL.md` is read by several agents and is
what OpenSpec itself generates.

## What Changes

- `webcpporg/proposals` gains `.agents/skills/`: OpenSpec 1.10.0's own skills (`openspec-propose`,
  `openspec-explore`, `openspec-apply-change`, `openspec-update-change`, `openspec-sync-specs`,
  `openspec-archive-change`), generated by `openspec init --tools agents` and adapted to the
  repository's several OpenSpec roots, and webcpp's `webcpp-openspec-proposal`,
  `webcpp-reference-status` and `webcpp-text-and-commits`.
- The proposals repository gains a short `AGENTS.md`, as every library has, which points to the
  superproject's and names the skills.
- `tools/proposals_test.py` pins that `tools/proposals.py check` reads `.agents/skills/` for
  forbidden text (it already reads every file).
- The superproject gains `.agents/skills/`: `webcpp-library-conventions`, `webcpp-port-methodology`,
  `webcpp-build-and-lanes`, `webcpp-docs-site-release` and `webcpp-text-and-commits`, and its
  `AGENTS.md` names them in its introduction.
- A requirement is added to the organization's specification: where skills live, what they may
  hold, and that the rules win over them.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `organization`: the requirement "Superproject: Agent skills" is added.

## Impact

- **Kind:** the organization (the rules' entry points for agents, in two repositories).
- **Implementation:** pull requests to https://github.com/webcpporg/proposals and
  https://github.com/webcpporg/webcpp from the branch `agent-skills`. No build, lint rule or
  workflow changes: the superproject's lint already reads every tracked file for the em dash and
  the banned word, and `tools/proposals.py check` every file of this repository.
- **Status:** draft.
- **Other proposals:** independent of `contributor-identity`; the skill `webcpp-text-and-commits`
  states the identity rule that change proposes (each contributor commits under their own
  identity), so the two should be decided together or the skill adjusted to the decision.
