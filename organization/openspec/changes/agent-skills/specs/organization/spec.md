## ADDED Requirements

### Requirement: Superproject: Agent skills
The superproject and the proposals repository SHALL keep agent skills in `.agents/skills/<name>/SKILL.md`, one directory per skill named in kebab case, each `SKILL.md` opening with YAML front matter whose `name` equals the directory and whose `description` says when the skill applies. A skill MUST point to the rules that apply (the chapter of the superproject's `AGENTS.md`, `CONTRIBUTING.md` or the organization's specification) and list the steps and commands of its task, without restating those rules at length; where a skill and a rule disagree, the rule wins. Skills follow the rules on text of every file: English, no em dash, no banned word, no personal data. The proposals repository holds OpenSpec's own skills, generated by OpenSpec 1.10.0 and adapted to its several OpenSpec roots, and `openspec init` is never run in the repository itself, since it would create a root `openspec/`. Each repository's `AGENTS.md` names its skills.

#### Scenario: An agent writes a proposal
- **WHEN** an agent in the proposals repository is asked to propose a change to a library
- **THEN** the skill `webcpp-openspec-proposal` sends it to `CONTRIBUTING.md` and the organization's specification, and it runs `openspec` from `libraries/<name>/`

#### Scenario: A skill with forbidden text
- **WHEN** a `SKILL.md` under `.agents/skills/` of the proposals repository holds an em dash
- **THEN** `python3 tools/proposals.py check` fails, naming the file and the line

#### Scenario: A skill and a rule disagree
- **WHEN** a chapter of the superproject's `AGENTS.md` changes a rule a skill cites
- **THEN** the chapter is followed, and the skill is updated to point to it
